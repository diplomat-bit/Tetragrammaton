#### Section 1: The Anatomy of Namespace Permeability
Linux namespaces are not hardware partitions; they are pointers in a kernel struct. Specifically, `nsproxy` inside `task_struct`.

When corporate IT runs containers, they leave `SYS_ADMIN`, `NET_ADMIN`, or mount capabilities open because their senior engineers got tired of debugging permissions. What happens? An attacker leverages unmasked `/proc/sys` entries, accesses shared `/dev/shm` IPC buffers, or mounts host cgroups to read raw host memory.

In sovereign systems, we enforce:
1. **User Namespace Remapping:** Container UID 0 (root) must map strictly to an unprivileged UID (e.g., UID 100000) on the host.
2. **Immutable Read-Only Root Filesystems:** No binary execution from writable directories. `/tmp` and `/run` mounted `noexec`, `nosuid`, `nodev`.
3. **Dropping All 38 Linux Capabilities:** Restoring only the absolute minimum (usually zero for pure network compute nodes).

### Session 06: Zero-Knowledge Proofs & Confidential Ledger Settlement (zk-SNARKs & Bulletproofs)
**Instructor:** The Sovereign Architect  
**Location:** Secure Virtual Terminal / Sovereign Node 06  
**Subject:** Privacy-Preserving Compliance, Proof of Solvency Without Balance Disclosure, and Circom Arithmetic Circuits

#### Opening Lecture: The Fallacy of Radical Transparency
Corporate systems swing between two catastrophic extremes: either everything is an insecure plain-text database exposed to every disgruntled internal administrator, or they attempt to put customer financial records onto public, unshielded distributed ledgers.

Both are fatal. In high finance, **confidentiality is an existential prerequisite**. If a market maker’s position, balance, or settlement destination is broadcast across an open ledger, front-running bots and predatory desks will exploit the slippage and destroy their liquidity margins.

Zero-Knowledge Proofs (ZKPs) solve the fundamental paradox of financial engineering: **How do you mathematically prove that a transaction is completely valid and compliant with all regulatory constraints, without revealing the balance, the counterparty, or the amount to any unauthorized observer?**

#### Section 1: Arithmetic Circuits & Constraint Systems (R1CS)
ZKPs are not magic; they are mathematics. We compile computation into Rank-1 Constraint Systems (R1CS) of the form:
$$(A \cdot s) \times (B \cdot s) - (C \cdot s) = 0$$

In financial verification, we use arithmetic circuits to prove:
1. **Conservation of Value:** $\sum \text{Inputs} = \sum \text{Outputs} + \text{Fee}$
2. **Non-Negativity:** Proving that no balance is negative without revealing the balances (preventing underflow exploits).
3. **Membership Inclusion:** Proving an account exists inside a Merkle tree of accredited accounts without revealing which account it is.

```circom
// solvency_proof.circom - Proving balance exceeds reserve threshold without revealing balance
pragma circom 2.1.6;

include "circomlib/circuits/comparators.circom";
include "circomlib/circuits/poseidon.circom";

template SolvencyVerifier() {
    // Private Inputs (Known only to the Sovereign Ledger)
    signal input accountBalance;
    signal input accountSecret;

    // Public Inputs (Known to Auditors & Regulators)
    signal input minimumReserveRequirement;
    signal input balanceCommitment;

    // 1. Verify that commitment matches hash(accountBalance, accountSecret)
    component hasher = Poseidon(2);
    hasher.inputs[0] <== accountBalance;
    hasher.inputs[1] <== accountSecret;
    hasher.out === balanceCommitment;

    // 2. Prove accountBalance >= minimumReserveRequirement
    component comp = GreaterEqThan(64); // 64-bit integer precision
    comp.in[0] <== accountBalance;
    comp.in[1] <== minimumReserveRequirement;

    // Enforce that comparison result is strictly 1 (True)
    comp.out === 1;
}

component main {public [minimumReserveRequirement, balanceCommitment]} = SolvencyVerifier();
```

#### Section 2: Generation and On-Chain/In-Enclave Verification
Once the circuit is compiled with `circom` and initialized via a trusted setup (Powers of Tau), we generate a zero-knowledge proof ($\pi = [A, B, C]$) using Groth16. The verification takes less than 3 milliseconds of compute time and consumes mere hundreds of bytes of memory. The auditor verifies the proof mathematically—knowing with certainty that the firm is solvent—without learning a single cent of the firm's true balances.

#### Section 1: The Anatomy of a High-Throughput In-Memory Order Book

```typescript
// sovereign_orderbook.ts - High-Performance Order Book Core
export interface Order {
  id: string;
  side: 'BUY' | 'SELL';
  price: number;
  size: number;
  timestamp: number;
}

export class OrderBookSide {
  private orders: Map<number, Order[]> = new Map(); // Price -> Orders (FIFO Queue)

  public insertOrder(order: Order): void {
    const queue = this.orders.get(order.price) || [];
    queue.push(order);
    this.orders.set(order.price, queue);
  }

  public getBestPrice(side: 'BUY' | 'SELL'): number | null {
    if (this.orders.size === 0) return null;
    const prices = Array.from(this.orders.keys());
    return side === 'BUY' ? Math.max(...prices) : Math.min(...prices);
  }

  public matchMarketSweep(requiredSize: number, side: 'BUY' | 'SELL'): { filledSize: number; vwap: number } {
    let remaining = requiredSize;
    let totalCost = 0;

    const sortedPrices = Array.from(this.orders.keys()).sort((a, b) => 
      side === 'BUY' ? a - b : b - a
    );

    for (const price of sortedPrices) {
      const level = this.orders.get(price) || [];
      while (level.length > 0 && remaining > 0) {
        const top = level[0];
        const fill = Math.min(remaining, top.size);
        top.size -= fill;
        remaining -= fill;
        totalCost += fill * price;

        if (top.size === 0) level.shift();
      }
      if (level.length === 0) this.orders.delete(price);
      if (remaining === 0) break;
    }

    const filledSize = requiredSize - remaining;
    const vwap = filledSize > 0 ? totalCost / filledSize : 0;
    return { filledSize, vwap };
  }
}
```

#### Section 1: Attaching Kernel Probes to Socket Connects
When any process in any container attempts to open a network socket, it must invoke the `sys_enter_connect` syscall. By attaching an eBPF program to this hook, we record the destination IP, port, and calling PID before the network packet even leaves the interface.

# sovereign_ebpf_monitor.py - Low-overhead Kernel Socket Forensics
from bcc import BPF

bpf_program = """
#include <uapi/linux/ptrace.h>
#include <net/sock.h>
#include <bcc/proto.h>

struct event_t {
    u32 pid;
    char comm[16];
    u32 saddr;
    u32 daddr;
    u16 dport;
};

BPF_PERF_OUTPUT(events);

int trace_connect_entry(struct pt_regs *ctx, struct sock *sk) {
    u32 pid = bpf_get_current_pid_tgid() >> 32;
    struct event_t event = {};

    event.pid = pid;
    bpf_get_current_comm(&event.comm, sizeof(event.comm));
    
    // Extract socket addresses
    event.saddr = sk->__sk_common.skc_rcv_saddr;
    event.daddr = sk->__sk_common.skc_daddr;
    event.dport = sk->__sk_common.skc_dport;

    events.perf_submit(ctx, &event, sizeof(event));
    return 0;
}
"""

b = BPF(text=bpf_program)
b.attach_kprobe(event="tcp_v4_connect", fn_name="trace_connect_entry")
